# STANDARDS.md

Code standards for the Gerenciador de Chamados project. Follow these when reading or writing any file. Cross-reference with `AGENTS.md` and the nearest `CONTEXT.md`.

## 1. Language & Naming

- Code, identifiers and user-facing messages are written in Brazilian Portuguese; technical terms stay in English (`PageRequest`, `repository`, `scheduler`, `input`).
- Classes/interfaces: `PascalCase`. Methods, fields and variables: `camelCase`. Constants: `UPPER_SNAKE_CASE`.
- Use-case methods are named in Portuguese by intent: `abrirChamado`, `listarChamadosParaAdmin`, `atualizarStatusChamado`.
- Keep the existing package casing, even when unconventional: `application/UserCase`.
- Roles are fixed strings: `ROLE_ADMINISTRADOR`, `ROLE_COLABORADOR`, `ROLE_MORADOR`.

## 2. Architecture & Layers

- `application`: ports/contracts only (`UserCase`, `Security`, `pagination`). No framework-heavy logic.
- `domain`: JPA entities (`domain/model`) and shared limits (`domain/validation`).
- `infrastructure`: adapters (`controller`, `service`, `repository`, `security`, `config`, `exception`).
- Controllers hold no business rule; they delegate to use cases through `WebControllerSupport`.
- Services implement a `UserCase` interface and are annotated `@Service` + `@Transactional(readOnly = true)`; write methods get `@Transactional`.
- Always use constructor injection; never `@Autowired` on fields.
- Page endpoints (GET) live in `controller/web`; mutations (POST/PATCH/PUT/DELETE) live in `controller/api`.
- Authorization is defense-in-depth: `@PreAuthorize` on controllers plus `AuthenticatedUserValidator.assert*` in services. Visibility rules are also enforced in SQL functions.

```java
@Service
@Transactional(readOnly = true)
public class UsuarioService implements UsuarioUseCase {

    private final UsuarioRepository usuarioRepository;

    public UsuarioService(UsuarioRepository usuarioRepository) {
        this.usuarioRepository = usuarioRepository;
    }
}
```

## 3. Persistence

- Schema is owned by Flyway; JPA runs with `spring.jpa.hibernate.ddl-auto=validate`. Never rely on Hibernate to create/alter tables.
- Migrations: `V{n}__descricao_snake_case.sql`, with a header comment describing purpose.
- When changing a SQL function signature, drop the previous signature before recreating it.
- Repositories extend `JpaRepository<Entity, UUID>`; IDs are UUIDs generated by the database.
- Complex filters and per-profile visibility live in PL/pgSQL functions called via `nativeQuery`; paginated queries provide a matching `countQuery`.
- Soft delete is done with the `ativo` column and `...AtivoTrue` finder methods.
- Entities use Lombok `@Getter/@Setter`; `@ManyToOne` relations are `LAZY`; collections are initialized `Set` fields; string columns use `length = ValidationLimits.*`.

## 4. Validation, Errors & Pagination

- Length/byte limits live in `ValidationLimits`; required text is normalized with `InputValidationSupport.normalizeRequiredText`.
- Throw only domain exceptions: `BusinessRuleException`, `ResourceNotFoundException`, `UnauthorizedOperationException`. `WebExceptionHandler` maps them to a redirect with `errorMessage`.
- Application-facing pagination uses `PageResult<T>`; convert from Spring Data with `PageResultMapper.fromPage`.
- Web defaults: page `0`, size `10`, max size `100` (handled by `WebControllerSupport.pageRequest`).

## 5. Web & Views

- Request payloads are Lombok `@Getter/@Setter` POJOs with the `Form` suffix. They carry no validation annotations; validation happens in services.
- Mutation controllers return `redirect:` and publish `successMessage`/`errorMessage` via `RedirectAttributes`.
- JSPs live under `/WEB-INF/jsp`, reuse `fragments/`, and build URLs with the `${ctx}` context path.
- Cross-cutting model attributes and known-exception handling go through `@ControllerAdvice` classes in `controller/web`.

## 6. Security

- Passwords are hashed with BCrypt via the configured `PasswordEncoder`; never store or log raw passwords.
- `/api/**` is stateless and authenticated by a JWT stored in the `jwt` cookie; web pages use session auth with a cookie CSRF token (`XSRF-TOKEN`).
- Secrets and environment-specific values come exclusively from environment variables (`.env`); never hardcode them in source.

## 7. Testing

- Every new feature needs E2E coverage; sensitive/heavy or external-dependency flows also get API integration tests; security and complex calculations also get unit tests (`AGENTS.md`).
- Unit tests: JUnit 5 + Mockito (`@ExtendWith(MockitoExtension.class)`), placed in a package mirroring the target, with descriptive Portuguese method names (`deve...`).
- Web integration: `@WebMvcTest` + `MockMvc` + `@MockitoBean`; authenticate via `WebTestAuthenticationFactory`.
- Database integration: `@SpringBootTest` through `integration/support/IntegrationTestSupport`, against the suite's PostgreSQL database (`TEST_DB_NAME`, default `gerenciador_chamados_test`), with Flyway creating the schema; use `@Transactional` for rollback.
- Run all tests with `docker compose run --rm test` (or `./mvnw test` with the database reachable).

## 8. Formatting & Style

- Indentation: 4 spaces. Braces on the same line (K&R). One public top-level type per file.
- No wildcard imports. Keep imports grouped and explicit.
- Aim for lines of ~120 columns.
- Utility classes have a private constructor and only `static` members; application DTOs are `record`s.
- Do not add inline comments in method bodies. Javadoc is allowed on use-case interfaces to explain the *why* of each operation.

## 9. Build & Configuration

- Java 21, Spring Boot 4, packaged as WAR.
- New configuration properties use the `app.*` prefix and `${ENV_VAR:default}` placeholders in `application.properties`.
- Check `pom.xml` before introducing any dependency and avoid breaking changes across major versions.
